# Appointment No-Show & Demand Forecasting Dashboard

A Streamlit dashboard for clinic staff with three main tools:
- **No-Show Risk Predictor** — enter a patient's appointment details, get a risk score
- **Demand Forecasting** — pick any future date and see the predicted appointment volume, with an optional specialty split
- **Insights** — the key patterns behind both models

## Files in this package

Only **4 files** — put them all in the same folder:

| File | What it is |
|---|---|
| `app.py` | The Streamlit app |
| `requirements.txt` | Python dependencies |
| `model_bundle.pkl` | The trained no-show classifier + demand forecaster, plus their encoders and feature lists |
| `data_bundle.pkl` | Historical daily data, insight tables, and headline stats that power the charts |

**Important:** the two `.pkl` bundles were generated by me from your real dataset, but using
GradientBoosting as a stand-in for XGBoost (I don't have XGBoost installed in my environment).
They make the app fully runnable right now. To use your **actual** trained models instead
(recommended for anything beyond a demo):

1. Open your Colab notebook and run it top to bottom, including the
   **"Export Artifacts for Streamlit App"** section at the very end.
2. That section downloads `model_bundle.pkl` and `data_bundle.pkl`, freshly built with real XGBoost.
3. Replace the two files in this folder with those downloads (keep the same filenames).

## Running locally

```bash
pip install -r requirements.txt
streamlit run app.py
```

Then open the local URL Streamlit prints (usually `http://localhost:8501`).

## Troubleshooting

**`ModuleNotFoundError: No module named '_loss'`** — this means the installed
scikit-learn version doesn't match the one the `.pkl` files were saved with
(pickled models are version-sensitive). Fix:

```bash
pip uninstall -y scikit-learn
pip install scikit-learn==1.8.0
```

If you re-export `model_bundle.pkl` from your own Colab notebook later, check
`import sklearn; sklearn.__version__` there and update `requirements.txt` to match.

## Deploying (optional)

The easiest free option is **Streamlit Community Cloud**:
1. Push this folder to a GitHub repo (all 4 files, including the two `.pkl` bundles).
2. Go to [share.streamlit.io](https://share.streamlit.io), connect the repo, set the main file to `app.py`.
3. It installs `requirements.txt` automatically and gives you a public URL.

## Notes on the Demand Forecasting tab

- Forecasts are generated **recursively**: each predicted day becomes the "lag" input for the
  next day's prediction, so accuracy naturally degrades a bit the further out you forecast —
  this is normal for time-series models and why the model performs best over the first ~1–2 weeks.
- Context features the model can't know in advance (SMS reminder rate, average patient age,
  weather, etc.) are filled in using the trailing 30-day average from historical data.
- The specialty filter is a **proportional estimate** (historical share × total forecast), not a
  separate per-specialty model — the underlying model was trained on total daily demand only.
